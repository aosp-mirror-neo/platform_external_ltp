# LTP Local Patches

This directory contains reference `.patch` files recording Android-specific
source modifications that are already committed directly in `external/ltp` on
top of the upstream LTP source tree.

Neither `tools/external_updater/updater.sh` nor `post_update.sh` automatically
applies `patches/*.patch` during upgrades; instead, `external_updater` merges
upstream commits via `git merge`, and these `.patch` files serve as an audit
trail and conflict-resolution reference for maintainers.

## Naming Convention
Patches are organized by theme and numbered sequentially:
- `16K-XXXX.patch`: Modifications related to 16KB page size support and x86_64
  16KB page size emulation (`include/pgsize_helpers.h`).
- `LAPI-XXXX.patch`: Linux API and Bionic compatibility fallback definitions.
- `LIB-XXXX.patch`: LTP library and helper function adjustments for Android
  virtualized/device environments.
- `SYS-XXXX.patch`: Specific syscall, procfs, and controller test adaptations
  for Android.

*(Note: Legacy `EAS-XXXX.patch` Energy Aware Scheduling custom tests have been
retired and removed from the tree in b/524012762).*

## Patch Lifecycle and Upstream Parity
To minimize maintenance overhead and merge conflicts during upgrades:
1. **Upstream First (`FROMLIST:` / `UPSTREAM:`)**: Fixes for generic test bugs
   or Bionic compatibility should be submitted to upstream LTP
   (`ltp@lists.linux.it`) and imported via `FROMLIST:` or `UPSTREAM:`. Do
   **not** add `.patch` files to `patches/` for changes that have already been
   submitted upstream (`FROMLIST:` or `UPSTREAM:`); add or update a `.patch`
   file here only when an Android-only source modification (`ANDROID:`) must be
   carried locally.
2. **Retiring Obsolete Patches**: When an upstream LTP upgrade includes an
   upstreamed or equivalent fix (such as loop device backoff polling removing
   `LIB-0001` or `mremap03` fixes removing `SYS-0004`), delete the superseded
   `.patch` file from `patches/` as part of the upgrade.

## Android-Specific Files and Diffs with Upstream
When comparing the Android `external/ltp` repository with clean upstream LTP,
several differences exist due to Android packaging and platform requirements.

### Android-Only Files
These files are maintained in `external/ltp` and do not exist in the upstream
LTP repository:
1.  **`Android.bp`, `gen.bp`, `testcases/Android.bp`**: Top-level `Android.bp`
    is hand-maintained (defining `ltp_defaults`, `ltp_test_defaults`, and
    Soong filegroups), whereas `gen.bp` and `testcases/Android.bp` are
    auto-generated by `android/tools/gen_android_build.sh`.
2.  **`android/`**: Contains Android-specific build scripts, the auto-generated
    `android/Android.bp`, Bionic compatibility headers (`android/include/`),
    skip lists (`android/tools/disabled_tests.txt` and `disabled_libs.txt`),
    and Docker build-generation helpers.
3.  **`METADATA`, `OWNERS`, `TEST_MAPPING`, `VERSION`, `post_update.sh`, `ltp_upgrade_guide.md`**:
    Android repository metadata, presubmit mappings, version tracking, and
    automated upgrade hooks.
4.  **`LICENSE`, `NOTICE`, `MODULE_LICENSE_GPL`**: Compliance and legal notices.
5.  **`runtest/fcntl-locktests_android`, `runtest/sched_low_mem`**: Custom
    Android-specific test runlists defining test commands executed in VTS.
6.  **`m4/ltp-pwritev2.m4`, `m4/ltp-syncfs.m4`**: Custom autoconf macros.

### Deleted Submodules
Upstream LTP uses git submodules for some external tools. Since Android
platform repositories do not use git submodules, the following directories are
omitted:
- `testcases/kernel/mce-test`
- `tools/kirk/kirk-src`
- `tools/ltx/ltx-src`
- `tools/sparse/sparse-src`

## Purpose
The `.patch` files in this directory document the outstanding Android-only C and
header modifications carried in `external/ltp` so maintainers can audit local
divergence and resolve merge conflicts when synchronizing with upstream LTP via
`tools/external_updater/updater.sh` and `post_update.sh`.
